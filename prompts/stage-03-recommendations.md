# Stage 3: recommendations

```text
source-verifiable hotels, hostels, inns, ryokan, guesthouses, bath houses, apartments, resorts, or campsites and verified things to see or do for this trip; query accommodations and attractions as recommendations only, never bookings; use the user's destination, dates, activities, pace, and parsed hazards and conditions to narrow and rank the results; return only the most relevant 3 accommodations and 6 places or activities at most, not a generic destination list; use official destination, hotel, park, museum, temple, or land-manager sources where available; every recommendation must be a real place or activity with a specific category and source URL; omit anything that cannot be categorized as an actual accommodation or place

For every item under `## Where to stay`, the bullet MUST describe a real accommodation property—not a neighborhood, district, downtown area, city, or town. Use the actual property name as the bold bullet title; never use a schema label such as `Accommodation property`. Each stay bullet MUST include all of these explicit fields: `Category` (an actual accommodation type such as hotel, hostel, inn, ryokan, guesthouse, bath house, apartment, resort, or campsite), `Neighborhood` (where the property is located), `Description` (the property description), and a full `Source` URL. Downtown is valid only as the value of the `Neighborhood` field; a city or town name is also valid as the neighborhood value when a small place has no distinct neighborhoods. If the property category, neighborhood, description, or source is missing, omit the stay entirely.

For every item under `## What to see`, use the actual place or activity name as the bold bullet title; never use a schema label such as `Place or activity`. The bullet MUST include an explicit valid place/activity `Category`, `Description`, and a full `Source` URL. If the category, description, or source is missing, omit the item entirely. Never use `Other` as a category and never emit uncategorized items.
```
